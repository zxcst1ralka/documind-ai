
# Локальная приёмка

| Проверка | Результат |
| --- | --- |
| Docker Compose и Alembic | Стек на Windows Docker Desktop запустился. Миграция OCR `0002` применилась к существующей базе. `alembic check` подтвердил соответствие схемы. |
| Backend | 19 тестов Pytest и Ruff прошли. Включены ротация сессий, проверка Origin, изоляция документов, очередь, парсинг, OCR и экспорт. |
| Frontend | Линт, TypeScript, 4 теста Vitest и production-сборка прошли. |
| Playwright | 3 сценария на отдельном стеке. Проверены регистрация, загрузка, ссылки на источники на двух типах экрана, анализ, сравнение, экспорт, удаление, мобильная главная, смена темы и переход от OCR-цитаты к странице PDF. |
| Реальный AI | Ollama с Qwen2.5 3B ответил по PDF без текстового слоя. Проверены индексация E5, SSE, ссылка на распознанную страницу, краткий и структурированный анализ договора с источником. |
| OpenAI-совместимый API | Проверены обнаружение модели и потоковый ответ через локальный `/v1` Ollama. Облачная авторизация требует отдельной конфигурации. |
| OCR | Русский и английский текст распознан в вымышленном скане. Тест смешанного PDF подтвердил сохранение нативного текста и правильного номера распознанной страницы. |
| Демо | Команда создала шесть вымышленных файлов, чат-пример и сохранённое сравнение. Попытка удаления из демо-аккаунта вернула 403. |
| Безопасность | npm audit, pip-audit и отдельная проверка версии CPU PyTorch завершились без известных уязвимостей. Gitleaks не обнаружил секретов в выгружаемых исходниках. |
| Swagger | Схема и UI загрузились в браузере. Доступна авторизация Bearer. |
| Адаптивность | Главная проверена в Chromium на ширинах 375, 768, 1024 и 1440 px в обеих темах. Интерактивный пример доступен с клавиатуры. |
| Материалы | Скриншоты сняты с запущенного приложения на вымышленных документах. [GIF](screenshots/workflow.gif) показывает загрузку, библиотеку, PDF и открытый источник. |

В ходе приёмки исправлены несовместимость Redis-клиента с Kombu,
MIME-тип PDF-воркера у Nginx, доступные имена полей выбора документов
и обработка ответа модели с пропущенным маркером источника.

Обязательные проверки CI описаны в GitHub Actions. Таблица фиксирует
локальную приёмку. Проверка AI проводилась с Ollama. Для облачного
провайдера требуется серверная конфигурация и ключ владельца установки.
Результаты аудита относятся к зависимостям приложения, а проверку
контейнерных образов и конфигурации хоста следует провести перед
внешним развёртыванием. См. [запуск и настройки](DEPLOYMENT.md).

## Сверка с ТЗ после редизайна

Проверка от 28 ноября 2026 года опирается на приоритетное уточнение
о портфельном назначении проекта. Тарифы, подписки, биллинг и админ-панель
исключены этим уточнением. Лесная палитра и новый шрифт заголовков выбраны
после запроса на редизайн. Описание оформления есть в [DESIGN.md](DESIGN.md).

| Область | Что подтверждено |
| --- | --- |
| P0 · приложение | Работают авторизация с ротацией сессий, библиотека, фоновая обработка, изоляция ресурсов, семантический поиск pgvector и потоковый чат с проверяемыми источниками. |
| P1 · рабочие сценарии | Реализованы анализ договора, сравнение версий, экспорт PDF/DOCX/Markdown и импорт CSV/XLSX. Демо-команда создала шесть учебных файлов, чат с источником и сравнение. Попытка удаления из демо-аккаунта вернула HTTP 403. |
| Архитектура и поставка | Сервисы соответствуют схеме. Nginx обслуживает React и FastAPI, PostgreSQL хранит метаданные и векторы, MinIO хранит оригиналы, Celery через Redis обрабатывает документы. Есть OpenAPI, Compose, CI и двуязычный README. |
| Повторный прогон | Alembic, Ruff, ESLint, TypeScript и штатная Docker-сборка фронтенда прошли. Pytest — 19, Vitest — 4, Playwright — 3. Ollama Qwen2.5 3B ответил по скану через SSE, вернул проверяемую ссылку на страницу OCR и сформировал структурированный анализ договора. |

Сравнение работает по строкам извлечённого текста. Отдельной таблицы
`audit_logs` нет. Теги хранятся в JSONB-поле документа. Компоненты интерфейса
собраны на Radix и Tailwind с собственными стилями. Поиск использует векторы
pgvector, гибридное ранжирование указано в ТЗ как опциональное.
В повторном прогоне использовался локальный Ollama. Проверка развёртывания
с облачным ключом остаётся отдельной задачей.
